# Personal news — Feed Reader

یک وب‌اپ تک‌فایلی برای خواندن فیدهای RSS و Atom، با ظاهر و رفتاری الهام‌گرفته از صفحه‌ی **Personal news** مرورگر اپرا.
کل برنامه داخل یک فایل `feed-reader.html` است (HTML + CSS + JavaScript خالص، بدون وابستگی و بدون build).

## ویژگی‌ها

- **تشخیص خودکار مسیر فید:** با وارد کردن آدرس یک سایت (مثلاً `digiato.com`) مسیر RSS/Atom آن را پیدا می‌کند.
- **دو نمای نمایش:** لیستی و شبکه‌ای (mosaic) که چیدمان کارت‌ها را بر اساس داشتن یا نداشتن عکس تنظیم می‌کند.
- **مدیریت عکس:** عکس فید را بررسی می‌کند و در صورت نبودن یا کوچک بودن، `og:image` صفحه‌ی مقاله را امتحان می‌کند.
- **گروه‌بندی زمانی:** Most recent، Today، Yesterday، This week، Last week، Earlier.
- **ذخیره‌سازی محلی:** منابع، نوع نمایش، پروکسی و نتیجه‌ی بررسی عکس‌ها در `localStorage` می‌مانند.
- **موبایل:** در عرض کم سایدبار پنهان می‌شود و به‌جای آن نوار افقی از چیپ‌ها (`#mnav`: Top 50، منابع، Add sources) بالای صفحه می‌آید. کارت‌های لیست هم ارتفاع خودکار دارند تا عنوان بریده نشود.
- **پشتیبانی از متن راست‌به‌چپ:** عنوان‌ها و خلاصه‌ها با `dir="auto"` نمایش داده می‌شوند.

## اجرا

1. فایل `feed-reader.html` را در مرورگر باز کنید، یا آن را روی هر هاست ایستا (مثل GitHub Pages) بگذارید.
2. به **Add sources** بروید، آدرس یک سایت یا فید را وارد کنید و روی **Add** بزنید.

> **نکته‌ی مهم (CORS):** مرورگر اجازه نمی‌دهد یک صفحه‌ی وب مستقیماً محتوای بیشتر سایت‌های دیگر را بخواند.
> برنامه اول مستقیم تلاش می‌کند، سپس از پروکسی‌های عمومی `allorigins` و `corsproxy.io` کمک می‌گیرد.
> این پروکسی‌ها گاهی کند یا ناپایدارند. در پایین صفحه‌ی Add sources می‌توانید پروکسی شخصی خودتان را وارد کنید
> (مثلاً یک Cloudflare Worker): `https://my-proxy.workers.dev/?url={url}`.
>
> همچنین در صفحه‌های منتشرشده‌ی Claude این برنامه کار نمی‌کند، چون آن صفحه‌ها اجازه‌ی درخواست به سایت‌های دیگر را ندارند.
> فایل را محلی یا روی هاست خودتان اجرا کنید.

## ساختار فایل

فایل سه بخش دارد:

| بخش | محتوا |
|---|---|
| `<style>` | تم تیره، چیدمان سایدبار، کارت‌ها، ردیف‌های mosaic، صفحه‌ی افزودن منبع |
| `<body>` | اسکلت ثابت صفحه: هدر، سایدبار (`#side`)، عنوان و دکمه‌ها (`.top`)، ناحیه‌ی محتوا (`#view`)، دیالوگ پیش‌نمایش (`#dlg`) |
| `<script>` | تمام منطق برنامه (در ادامه توضیح داده شده) |

صفحه مثل یک برنامه‌ی تک‌صفحه‌ای کار می‌کند: `render()` بر اساس مقدار `state` محتوای `#side` و `#view` را دوباره می‌سازد.

## بخش اول: حالت برنامه (state)

```js
let sources  = store.get("sources", []);   // [{url, title}]  منابع کاربر
let articles = {};                         // url منبع -> آرایه‌ی خبرها (فقط در حافظه)
let state    = {page: ..., src: null};     // صفحه‌ی فعلی و منبع انتخاب‌شده
let viewMode = store.get("view", "list");  // "list" یا "grid"
```

- `sources` و `viewMode` در `localStorage` ذخیره می‌شوند. `articles` فقط در حافظه است و با هر بار باز کردن صفحه دوباره از شبکه گرفته می‌شود.
- `state.page` برابر `"news"` یا `"add"` است. `state.src` آدرس منبع انتخاب‌شده در سایدبار است و `null` یعنی همه‌ی منابع (Top 50).
- اگر هیچ منبعی ذخیره نشده باشد، برنامه مستقیم صفحه‌ی `add` را باز می‌کند.

### `store`
یک پوشش ساده روی `localStorage` با `get(key, default)` و `set(key, value)`.
هر دو در `try/catch` هستند، چون در بعضی محیط‌ها (مثل حالت خصوصی یا صفحه‌های محدودشده) دسترسی به `localStorage` خطا می‌دهد و برنامه نباید به‌خاطر آن از کار بیفتد.

### `CATALOG`
فهرست ثابت منابع پیشنهادی (عنوان + آدرس فید). در بخش Recommended صفحه‌ی Add sources و کاشی‌های پایین صفحه‌ی اخبار استفاده می‌شود.

### `COMMON_PATHS`
فهرست مسیرهای رایج فید (`/feed`, `/rss`, `/atom.xml`, `/feed.xml`, `/index.xml`, ...) که هنگام تشخیص خودکار امتحان می‌شوند.

## بخش دوم: شبکه

### `proxies()`
فهرستی از توابعی برمی‌گرداند که هر کدام یک آدرس را به آدرس قابل‌درخواست تبدیل می‌کنند. ترتیب:
1. پروکسی شخصی کاربر (اگر تنظیم شده باشد؛ اگر آدرس `{url}` داشته باشد جایگزین می‌شود، وگرنه به‌عنوان پیشوند می‌آید)
2. درخواست مستقیم
3. `api.allorigins.win`
4. `corsproxy.io`

### `fetchText(url, ms)`
متن یک آدرس را می‌گیرد. پروکسی‌ها را به ترتیب امتحان می‌کند و با هر کدام که پاسخ موفق داد برمی‌گردد.
هر تلاش با `AbortController` محدود به `ms` میلی‌ثانیه است (پیش‌فرض ۹ ثانیه). اگر همه شکست بخورند خطای آخر پرتاب می‌شود.

## بخش سوم: تجزیه‌ی فید

### `parseFeed(text)`
متن XML را با `DOMParser` می‌خواند و یک شیء `{kind, title, items}` برمی‌گرداند (یا `null` اگر فید معتبر نبود).

- اگر ریشه `rss` یا `rdf` باشد، **RSS** است: عنوان از `channel`، و هر `item` شامل `title`, `link`/`guid`, `pubDate`/`date` و محتوا از `content:encoded` یا `description`.
- اگر ریشه `feed` باشد، **Atom** است: هر `entry` با `link[rel=alternate]`, `published`/`updated` و محتوا از `content` یا `summary`.
- عکس هر خبر به ترتیب از این‌ها برداشته می‌شود: `enclosure` از نوع تصویر، `media:thumbnail`، `media:content`، و در آخر اولین `<img>` داخل متن خبر (`firstImg`).
- از `getElementsByTagNameNS("*", ...)` استفاده شده تا فیدهایی که namespace دارند (مثل `media:` و `content:`) هم خوانده شوند.

توابع کمکی:
- `firstImg(html)`: با regex اولین `src` تصویر را از HTML درمی‌آورد.
- `plain(html)`: HTML را به متن ساده تبدیل می‌کند (برای خلاصه‌ی کارت‌ها).

## بخش چهارم: تشخیص خودکار RSS/Atom

### `looksFeed(text)`
بررسی سریع اینکه ۳۰۰۰ کاراکتر اول متن شبیه فید است (وجود `<rss`, `<feed` یا `<rdf:RDF`).

### `normalizeUrl(s)`
ورودی کاربر را به آدرس کامل تبدیل می‌کند (در صورت نبودن، `https://` اضافه می‌شود).
اگر ورودی فاصله داشته باشد یا نقطه نداشته باشد، `null` برمی‌گرداند. در این حالت ورودی کلیدواژه حساب می‌شود و بین `CATALOG` جستجو می‌شود.

### `probe(url)`
آدرس را می‌گیرد و اگر واقعاً فید معتبر بود `{url, title, kind, count}` برمی‌گرداند، وگرنه `null`.

### `discover(input, onStep)`
هسته‌ی تشخیص فید. مراحل:

1. **خود آدرس فید است؟** صفحه گرفته می‌شود و اگر فید بود، همان برگردانده می‌شود.
2. **تگ‌های `<link rel="alternate">`:** در HTML صفحه دنبال `type="application/rss+xml"` یا `atom+xml` (و نوع‌های `xml` مشابه) می‌گردد. آدرس‌های نسبی نسبت به `<base>` یا آدرس صفحه کامل می‌شوند.
3. **لینک‌های `<a>` شبیه فید:** لینک‌هایی که مسیرشان شامل `feed`, `rss`, `atom` یا پسوند `.rss`/`.atom` است.
4. هر نامزد پیداشده با `probe` واقعاً دانلود و تجزیه می‌شود (حداکثر ۸ نامزد، به‌صورت موازی).
5. **مسیرهای رایج:** اگر هنوز چیزی پیدا نشده، `COMMON_PATHS` روی دامنه‌ی اصلی و روی مسیر واردشده امتحان می‌شود، در دسته‌های ۶تایی تا اولین فید معتبر.

آرگومان `onStep` پیام وضعیت («Checking page…» و ...) را به رابط کاربری می‌دهد.

## بخش پنجم: عکس‌ها و بارگذاری منابع

### مدیریت عکس
هر خبر یک پرچم `ok` می‌گیرد که یعنی «عکس قابل‌قبول دارد».

- `probeImg(u)`: عکس را در یک `Image()` بارگذاری می‌کند (با `referrerPolicy="no-referrer"` و timeout هشت‌ثانیه‌ای). اگر بارگذاری شد و اندازه‌اش حداقل ۳۰۰×۱۶۰ بود، `true` برمی‌گرداند. **عکس کوچک یا خراب یعنی «بدون عکس».**
- `ogImage(link)`: صفحه‌ی خود مقاله را می‌گیرد و متای `og:image` یا `twitter:image` را برمی‌گرداند.
- `resolveItem(a)`: اول نتیجه‌ی ذخیره‌شده‌ی `ic` را نگاه می‌کند. اگر نبود، عکس فید را با `probeImg` بررسی می‌کند؛ اگر رد شد، `ogImage` را امتحان و دوباره بررسی می‌کند. در پایان `a.done = true` می‌شود و نتیجه ذخیره می‌شود.
- `ic`: کش عکس‌ها `{لینک خبر: {img, ok}}` در `localStorage`، با سقف ۶۰۰ مورد. ذخیره‌کردن با `icSave()` و با تأخیر یک‌ثانیه‌ای (debounce) انجام می‌شود.
- `limit(fn)`: صف ساده‌ای که حداکثر ۶ درخواست هم‌زمان اجازه می‌دهد تا مرورگر زیر بار درخواست‌های عکس و مقاله له نشود.
- `cssUrl(u)`: آدرس را برای استفاده داخل `background-image` امن می‌کند (نقل‌قول و پرانتز را escape می‌کند).

### `loadSource(s)`
فید یک منبع را می‌گیرد، خبرها را در `articles[s.url]` می‌گذارد و برای ۳۰ خبر تازه‌تر `resolveItem` را راه می‌اندازد. نتیجه‌ی خطا یک آرایه‌ی خالی است.

### `refreshAll()`
منابعی که هنوز بارگذاری نشده‌اند را به‌صورت موازی می‌گیرد و بعد `render()` را صدا می‌زند.

### `soon()`
یک `render` با تأخیر ۳۵۰ میلی‌ثانیه (debounce). چون نتیجه‌ی عکس‌ها یکی‌یکی می‌رسد، بدون این تابع صفحه برای هر عکس بازسازی می‌شد. اگر کاربر در صفحه‌ی Add sources باشد، فقط سایدبار به‌روز می‌شود تا نتایج جستجو پاک نشود.

### `addSource` و `removeSource`
افزودن و حذف منبع در `sources` و `localStorage`. حذف، خبرهای آن منبع را هم از `articles` پاک می‌کند و اگر منبعی نماند به صفحه‌ی Add sources می‌رود.

## بخش ششم: رندر

### `esc(s)`
متن را برای قرار گرفتن داخل HTML escape می‌کند. تمام متن‌هایی که از فید یا کاربر می‌آیند از این تابع رد می‌شوند تا تزریق HTML ممکن نباشد.

### `ago(ts)` و `group(ts)`
- `ago`: زمان نسبی مثل `12 m ago`, `3 h ago`, `2 d ago`.
- `group`: نام گروه زمانی: Most recent (کمتر از ۳ ساعت)، Today، Yesterday، This week (تا ۷ روز)، Last week (تا ۱۴ روز) و Earlier.

### `renderSide()`
سایدبار: Top 50، فهرست منابع با دکمه‌ی حذف (×) که با hover ظاهر می‌شود، و لینک Add sources.

### `cardHtml(a)`
HTML یک کارت خبر. اگر `a.ok` باشد کارت از نوع `.m` است و بخش عکس دارد، وگرنه `.tx` (متنی) است. زمان فقط در کارت‌های عکس‌دار دیده می‌شود.

### `mosaic(items)`
چیدمان شبکه‌ای. انواع ردیف:

| ردیف | چیدمان |
|---|---|
| `a` | سه کارت عکس‌دار هم‌عرض |
| `b` | دو کارت عکس‌دار پهن + یک ستون باریک از ۱ تا ۳ کارت متنی |
| `d` | دو کارت عکس‌دار |
| `c` | حداکثر ۴ کارت (ترکیبی) |
| `c tt` | حداکثر ۶ کاشی متنی کوچک پشت‌سرهم |

ردیف‌ها به‌نوبت بین `a` و `b` عوض می‌شوند.

**نکته‌ی مهم: حفظ ترتیب زمانی.** هر ردیف فقط از خبرهای **پشت‌سرهم** ساخته می‌شود (تابع `takeB` یک بلوک پیوسته از لیست برمی‌دارد و وقتی عکس‌دار سوم یا متنی چهارم رسید متوقف می‌شود). بنابراین ردیف پایین‌تر همیشه قدیمی‌تر از ردیف بالاتر است. فقط داخل یک ردیف ممکن است جای کارت‌ها عوض شود (عکس‌دارها کنار هم و متنی‌ها در ستون باریک).

### `renderNews()`
1. خبرهای منابع انتخاب‌شده را جمع می‌کند، بر اساس تاریخ نزولی مرتب می‌کند و ۵۰ تای اول را نگه می‌دارد.
2. فقط خبرهایی که `done` شده‌اند (وضعیت عکسشان معلوم است) نمایش داده می‌شوند، تا چیدمان بعداً به‌هم نریزد.
3. خبرها را به گروه‌های زمانی تقسیم می‌کند و برای هر گروه یا `mosaic` (شبکه) یا فهرست ساده‌ی کارت‌ها (لیست) می‌سازد.
4. در پایان متن «END OF NEWS STREAM» و سه کاشی از منابع پیشنهادی که هنوز اضافه نشده‌اند را می‌گذارد.

### `hydrateRec()`
برای کاشی‌های Recommended، فید آن منبع را می‌گیرد و عکس اولین خبر را به‌عنوان پس‌زمینه می‌گذارد. نتیجه در `recImg` کش می‌شود.

### `renderAdd()`
صفحه‌ی افزودن منبع: کادر جستجو، جای نتیجه‌ی تشخیص فید، فهرست Recommended با دکمه‌های Preview و Add، و کادر تنظیم پروکسی.

### `render()`
تابع اصلی رندر. سایدبار را می‌سازد، کلاس `grid` را روی `body` می‌گذارد یا برمی‌دارد، دکمه‌های نما و «Remove from my sources» را نشان یا پنهان می‌کند و محتوای `#view` را بر اساس `state.page` عوض می‌کند.

## بخش هفتم: رویدادها

برنامه از **event delegation** استفاده می‌کند: فقط دو شنونده‌ی کلیک و یک شنونده‌ی `input` روی `document` هست و رفتار هر دکمه از ویژگی‌های `data-*` آن خوانده می‌شود:

| ویژگی | کار |
|---|---|
| `data-go` | رفتن به صفحه‌ی اخبار یا Add sources |
| `data-src` | انتخاب یک منبع در سایدبار |
| `data-rm` / `data-rmcur` | حذف منبع (از سایدبار / دکمه‌ی بالای صفحه) |
| `data-v` | تغییر نمای لیست/شبکه |
| `data-addrec` | افزودن منبع پیشنهادی |
| `data-prev` | پیش‌نمایش منبع پیشنهادی در دیالوگ |
| `data-found` | افزودن فیدی که تشخیص خودکار پیدا کرده |

**کادر جستجو:** با هر تایپ، بعد از ۴۵۰ میلی‌ثانیه (debounce) یکی از دو کار انجام می‌شود:
- اگر ورودی شبیه آدرس باشد، `discover` اجرا می‌شود و نتیجه‌ها نشان داده می‌شوند.
- وگرنه بین `CATALOG` جستجوی کلیدواژه‌ای می‌شود.

متغیر `seq` شماره‌ی آخرین جستجو را نگه می‌دارد تا پاسخ یک جستجوی کهنه‌تر، نتیجه‌ی جستجوی تازه‌تر را پاک نکند.

## بخش هشتم: CSS

- **رنگ‌ها:** متغیرهای `:root` (`--bg`, `--panel`, `--blue`, ...).
- **کارت‌های لیست:** `.card` فلکس افقی با ارتفاع ثابت و عکس ۲۴۸ پیکسلی.
- **ردیف‌های شبکه‌ای (`.row`):** با **Flexbox** ساخته شده‌اند و فاصله‌ها با `margin` است، نه `gap`.
  کارت‌ها `flex: 1 1 0` دارند تا عرضشان برابر شود و در ردیف `b` دو کارت اول `flex-grow: 2` می‌گیرند.
- **ارتفاع عکس:** متغیر `--ih` است که با واحد `cqw` از عرض کانتینر (`.feed` با `container-type: inline-size`) محاسبه می‌شود.
  بخش متن کارت ارتفاع ثابت ۱۵۰ پیکسل دارد.
- **عرض کم:** با `@container (max-width: 600px)` ردیف‌ها دو‌ستونه می‌شوند و کارت سوم ردیف `a` به‌صورت افقی در کل عرض قرار می‌گیرد.
- **کاشی‌های متنی:** حروف بزرگ برای نام منبع، حذف زمان و عنوان کوچک‌تر.

## محدودیت‌ها

- برای فیدهایی که CORS ندارند، برنامه به پروکسی تکیه دارد. برای استفاده‌ی جدی یک پروکسی شخصی بگذارید.
- از هر منبع فقط ۳۰ خبر تازه‌تر بررسی و نمایش داده می‌شود و در مجموع ۵۰ خبر.
- خبرها فقط در حافظه هستند و با هر بار باز کردن صفحه دوباره گرفته می‌شوند. به‌روزرسانی خودکار دوره‌ای وجود ندارد.
- فیدهایی که فقط با `http://` در دسترس‌اند، وقتی برنامه روی HTTPS سرو شود مستقیم لود نمی‌شوند (mixed content) و باید از پروکسی رد شوند.
- برنامه را فقط با بررسی سینتکس و یک آزمون منطق چیدمان بررسی کرده‌ام. چیدمان بصری نهایی را باید در مرورگر خودتان وارسی کنید.
